## 3. Сильные стороны

- **Разделение ответственности.** `db.py` — данные, `routes.py` — HTTP, `weather.py`/`feed.py` — внешние источники, `image_gen.py` — Pillow, `scheduler.py` — cron, `timeutils.py` — время. Модуль = одна задача. Дёргать такой код — одно удовольствие.
- **Очередь источников погоды с деградацией.** Open-Meteo → OpenWeatherMap → wttr.in, кэш `weather_cache.json`, при полном отказе — устаревший кэш (weather.py:244-310). Новости делают то же самое (feed.py:117-155). Кэши согласуются по схеме (`schema`) — аккуратно.
- **`timeutils.py`** — правильная привычка, спасшая от проблемы Docker/UTC. Плюс валидация IANA-пояса в конфиге.
- **Автомиграции без Alembic** (`db.py:54-68`) — для масштаба проекта идеально: идемпотентны через перехват `OperationalError`.
- **Конфиг через `pydantic-settings`** с префиксом `CORP_`, валидацией обязательных креденшелов и запретом слабого пароля.
- **numpy-виньетка** (`image_gen.py:258-282`) — умный компромисс производительности в чисто Pillow-модуле.
- **Прод-культура Docker:** непривилегированный пользователь, HEALTHCHECK, пример `nginx.conf` с TLS/cеcurу. Заголовки и volume изолированы.
- **Пользовательский контент редактируем без пересборки:** `data/holidays.json`, `data/quotes.json`, `staff.txt` в git, кэши и БД — вне git.

## 4. Проблемы

### 4.1. Реальные баги (чинить в первую очередь)

#### БАГ 1. `import_staff.py --no-reset` падает с `TypeError`
`reconcile()` в import_staff.py:129 делает `existing[rec["name"]]["synced"] = True`, но элементы `existing` — это `sqlite3.Row`, а не `dict`. Row не поддерживает присваивание:

```python
>>> row["synced"] = True
TypeError: 'sqlite3.Row' object does not support item assignment
```

**Проверено запуском.** Значит режим частичной досинхронизации (реальный сценарий после ручной добавки сотрудника через админку!) падает на первой же совпавшей записи.
**Фикс:** `existing = {row["name"]: dict(row) for row in conn.execute(...)}` (одна строка).

#### БАГ 2. Двойная генерация открыток утром + дубли в `greetings_log`
- Планировщик в `scheduler.py:36-40` генерирует открытку **без возраста** → файл `greeting_<ФИО>.jpg`.
- Роут `_get_birthday_items()` (routes.py:152-165) ищет файл **с возрастом** — `greeting_<ФИО>_37.jpg` — не находит и генерирует заново, затем `_cleanup_old_greetings()` (routes.py:121) **удаляет** файл, который только что сделал планировщик.

Итог: каждое утро планировщик впустую тратит секунды на генерацию, потом ТВ при первом открытии делает всё заново — прямо в HTTP-запросе. Плюс в `greetings_log` **попадают две записи** на человека (одна — от планировщика, вторая — от роута).
**Фикс:** единая функция «нужная картинка для сотрудника» (с age-тегом), которую вызывает и планировщик, и роут; `log_greeting` — из одного места.

#### БАГ 3. Из формы объявления нельзя очистить даты `date_from` / `date_to`
`update_announcement()` (db.py:378-447) использует `None` как маркер «не менять» (`if date_from is not None`). Поэтому обновить дату на «всегда показывать» (NULL в БД) из админки невозможно — пустое поле формы приедет как `None` и будет проигнорировано.
**Фикс:** sentinel-объект (`_SENTINEL`) в сигнатурах, чтобы отличать «не менять» от «стереть в NULL».

#### БАГ 4. `empty_rotation_seconds` настроен, но не работает
Конфиг и README обещают разную скорость ротации пустого информера, но в `informer.html` весь JS-ротатор использует одну константу `ROTATION_SECONDS` (informer.html:548). Значение `empty_rotation_seconds` только передаётся в контекст (routes.py:381) и дальше никак не используется.
**Фикс:** либо честно реализовать (две скорости: когда есть слайды и когда нет), либо удалить настройку, чтобы не вводить в заблуждение. Команде ЛАЙК — я за реализацию, это 10 минут в JS.

### 4.3. Надёжность

- **Нет тестов ни одного.** Для сервиса с БД, генерацией картинок и тремя внешними API — это главный системный риск. Два дня назад баг №1 в `import_staff` именно поэтому и дожил до проды.
- **`async def`-хендлеры с блокирующей работой внутри.** Все роуты объявлены `async def`, но внутри — синхронные SQLite, Pillow и сетевые запросы (routes.py:332-393). FastAPI крутит `async def` в **единственном event loop**: если ТАСС не отвечает 12 с, а следом Open-Meteo тупит ещё 12 с — **замирает весь сервис**, включая статику и админку. Худший случай — 36 секунд полного стопора рендера `/`.
  **Фикс:** для блокирующих хендлеров использовать обычные `def` (Starlette сам закинет в threadpool), тяжёлую генерацию картинок — в `BackgroundTasks`.
- **`auto_deactivate_expired()` на каждый просмотр** (routes.py:230) — UPDATE в БД при каждом рендере ТВ. Логичнее раз в час из планировщика.
- **Логирование в консоль** (main.py:19-23), файла нет.
- **`busy_timeout` не задан явно** (db.py:29). Дефолт sqlite3.connect = 5 с, так что совсем плохо не будет, но явный `connect(..., timeout=5.0)` + выполнение `PRAGMA journal_mode=WAL` только при инициализации — чище, чем переключать на каждом соединении.
- **HEALTHCHECK бьёт по тяжёлому `/`** (Dockerfile:28-29) — прогоняет генерацию картинок и сетевые вызовы «вхолостую». Нужен лёгкий `GET /healthz` (только статус БД).
- **4 коммита не запушены** — `git status` показывает отставание. Если диск умрёт — работа потеряна.

### 4.4. Безопасность

- **Basic Auth гоняет пароль открытым текстом**, пока портал не закрыт nginx+TLS. `nginx.conf` готов, но **документации по установке нет** (прежний `HTTPS_SETUP.md` удалён).
- **Пароль лежит открыто в `.env`** — захардить поддержку `CORP_ADMIN_PASSWORD_HASH` (bcrypt) для прода.
- **`bleach.clean()` без явного `protocols=`** (routes.py:102-107). Сейчас дефолт съедает `javascript:`, но полагаться на дефолты версии не стоит — задать `{"http","https","mailto"}`.
- **Токен CSRF привязан к IP+User-Agent** (csrf.py:96-107). За NAT у всех один внешний IP; смена IP по ходу сессии → 403 на формах. Для внутреннего сервиса терпимо, альтернатива — signed cookie.
- **JSON в `<script>` через `|safe`** (informer.html:531-533). Источники (свои `quotes.json`, санитизированный ТАСС, числовые прогнозы) — безопасны на практике, но «прошивка» неэкранированного JSON в script-блок — классический класс XSS. Одной функцией-эскейпом (`</script>` → `<\/script>`) закрывается.
- **Нет rate-limit на `/admin`** на уровне приложения — защита живёт только в nginx (nginx.conf:44-53).
- `a[target]` разрешён **без `rel="noopener"`** (routes.py:64) — в админке это не критично, но правило хорошее.

### 4.5. Производительность

- **Генерация открытки прямо в GET `/`** (routes.py:155-168) — при промахе кэша это 1–3 секунды на человека в критическом пути клиента. Плюс баг №2 гарантирует, что промах после 06:00 случается всегда.
- **405 цитат (~71 КБ) дважды в странице**: серверный `quote` + полный `quotes_json`, и ещё `news_json` + `forecast_all`. ТВ за один прогон отдаёт ~100 КБ+ разметки. На TV не критично, но набор растёт — стоит отдавать только «текущий» фрагмент.
- Таймауты внешних источников 12 с каждый, и они **сопровождают каждый рендер** (пока кэш не создан). Сthreadpool + фоновым наполнением кэша проблема уходит.

## 6. Вердикт

Проект перешёл в режим уверенного развития: прошлый список проблем закрыт почти полностью, появились новости, праздники, цитаты, нормальный Docker/Makefile и валидный контейнер. Это уже не прототип, а маленький прод-сервис.

Но в движении накопился долг: **два реальных бага** (`import_staff --no-reset`, двойная утренняя генерация), **блокирующий event loop** и **растущий мёртвый код** в незакоммиченном `weather.py`. Учитывая отсутствие тестов — трамплин для регрессий.

Порядок действий чистый и короткий: **закоммить и запушить → починить 2 бага → `def` вместо `async def` → pytest → только потом фичи.** После этого останутся только приятные задачи: карточки объявлений и живая бегущая строка.

Резюмируя одним предложением: **потолок в 6.2 из 10 — это не про архитектуру (она хорошая), а про дисциплину (коммиты, тесты, чистота). Прокачать её — 3–4 рабочих дня.**
