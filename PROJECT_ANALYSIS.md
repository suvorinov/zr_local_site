## 2. Сильные стороны

- **Разделение ответственности.** Каждый модуль делает ровно одно: `db.py` — данные, `routes.py` — HTTP, `weather.py` — прогноз, `image_gen.py` — Pillow, `scheduler.py` — cron. Дёргать такое — одно удовольствие.
- **Конфиг через env.** `pydantic-settings` с префиксом `CORP_` (config.py:73-78) + валидация обязательных админ-креденшелов (config.py:43-71). Грамотно.
- **Lifespan-контекст** (main.py:28-43) — корректная инициализация БД, планировщика и их остановка.
- **WAL для SQLite** (db.py:30) + `foreign_keys=ON` — правильный выбор для читающего сервиса.
- **Автомиграции** — `_run_migration()` (db.py:53-67) элегантно добавляет колонки без Alembic. Для масштаба проекта — в самый раз.
- **Кэш погоды 15 минут** с fallback на старый кэш при ошибке API (weather.py:90-122) — продумано.
- **numpy-виньетка** (image_gen.py:210-243) — ~100x быстрее поксельного цикла. Приятно видеть.

### 4.2. Дублирование логики

- **CSRF session_id вычисляется дважды** с одинаковым кодом: `routes.py:66-70` (`_get_session_id`) и внутри `csrf.py:107-109`. Вынеси в один модуль (`csrf.py`), и из routes просто импортируй.

### 4.3. Надёжность

- **Нет тестов вообще.** Для сервиса с БД, генерацией картинок и внешним API это риск. План — в §5 Фаза 1.
- **Часовой пояс.** Везде `datetime.now()` (db.py, weather.py, routes.py, scheduler.py) — локальное время процесса. В Docker образ `python:3.12-slim` отдаёт **UTC**, а `docker-compose.yml` не задаёт `TZ`. Итог: в контейнере после 00:00 по московскому времени дата «сегодня», время проверки ДР (06:00) и отсечка «сегодняшнего дня» погоды не совпадают с местными. `zoneinfo` доступен.
  - Быстрый фикс: `environment: TZ=Europe/Moscow` в docker-compose.
  - Правильный: настройка `CORP_TIMEZONE` + helper `now()` через `ZoneInfo`.
- **SQLite под конкуренцией.** `get_connection()` (db.py:17) не ставит `busy_timeout`. Когда планировщик пишет (поздравления) одновременно с запросом — возможен `database is locked`. WAL смягчает, но timeout стоит задать явно (`sqlite3.connect(..., timeout=5.0)`).
- **Запись на каждый просмотр.** `auto_deactivate_expired()` (UPDATE в БД) вызывается при каждом GET `/` через `_get_ticker_items()` (routes.py:201). Один раз в час это делал бы планировщик — и функционал тот же, и БД не дёргается на каждый рендер ТВ.
- **Логирование только в консоль** (main.py:19-23). В продакшене пригодится файл (RotatingFileHandler).

### 4.4. Безопасность

- **Basic Auth гоняет пароль открытым текстом**, если приложение не закрыто nginx+TLS. `nginx.conf` уже готов (TLS, security-заголовки, rate-limit `/admin`), но руководство `HTTPS_SETUP.md` удалено — документировать установку заново.
- **CSRF привязан к IP + User-Agent** (csrf.py:107-109). Офис часто сидит за общим NAT: у всех один внешний IP, и токен привязан к «одной сессии». UA спасает частично; флоат какого-нибудь прокси, меняющего IP по ходу сессии, — и форма падает с 403. Терпимо для внутреннего сервиса, но заслуживает альтернативу (signed cookie на стороне сервера).
- **bleach.clean() без явного `protocols=`** (routes.py:106-111). Дефолт отсекает `javascript:`, но лучше задать явно `protocols={"http","https","mailto"}` — чтобы не зависеть от дефолтов версии.

### 4.5. Производительность

- **Генерация картинки именинника прямо в HTTP-запросе.** Если утром планировщик не успел (рестарт после 06:00), GET `/` на лету вызывает Pillow+numpy (routes.py:127-145): ~1–3 сек на сотрудника, и страница ТВ «висит». Для ТВ это браузер всё равно перезагружает редко, но лучше не блокировать рендер — варианты: генерация в `BackgroundTasks`, или показать карточку-заглушку, а картинку подкинуть кэшем.
- **213 цитат (~32 КБ) целиком зашиваются в HTML** (routes.py:346, informer.html:533). На TV — норм, но если цитат станет 5000+, страница потолстеет. Оставить как есть, если набор держим умеренным.

## 6. Вердикт

Проект здоровый и по-хорошему консервативный: KISS здесь не лозунг, а практика.
Основные риски — не в архитектуре, а в операционном слое: часовой пояс в Docker, отсутствие тестов и «мёртвые» ветки кода, которые путают при развитии.

Порядок действий чистый: **закоммить текущее → вычистить мусор → закрыть надёжность (тесты/TZ/БД) → вернуть объявления карточками → документировать HTTPS.** После Фазы 1 — это уже не прототип на ТВ, а маленький, но продакшн-устойчивый сервис.
